# Goblin Stronghold — development

## Active foundation

The active implementation is the modern solution:

```text
GoblinStronghold.slnx
```

The historical `Goblin Fortress.sln`, XNA project, WinForms editors, bundled binaries and d20 libraries were removed from the active tree during the archival reset. Their last complete tracked state remains recoverable from Git commit `09ba2db` and the conclusions of the clean-room audit remain in `docs/legacy-audit.md`.

The current projects are:

- `src/GoblinStronghold.Simulation` — pure deterministic simulation and map generation;
- `src/GoblinStronghold.Godot` — thin Godot 4.7.2 .NET presentation probe;
- `src/GoblinStronghold.Headless` — executable validation scenario with no renderer;
- `tests/GoblinStronghold.Simulation.*.Tests` — four thematic projects for
  content, world, economy, and broader simulation scenarios; see
  `docs/testing.md`.

All active projects target `net10.0` and C# 14. The repository pins the .NET 10 SDK family through `global.json` while allowing newer .NET 10 feature bands.

The Godot 4.7.2 .NET desktop integration targets .NET 10 and has been verified against the locally installed Windows x64 editor and its headless host.

The game targets desktop PC only. Windows x64 is the primary development platform; Windows x64 and Linux x64 are intended release targets. Linux ARM64 and Raspberry Pi are experimental smoke-test targets without a performance promise. Mobile, web and console exports are outside scope.

The simulation and headless projects must avoid Windows-specific APIs. Linux x64 export and the experimental Linux ARM64/Raspberry Pi renderer and graphics stack still require end-to-end verification.

## Commands

Restore dependencies:

```powershell
dotnet restore .\GoblinStronghold.slnx
```

Build the active solution:

```powershell
dotnet build .\GoblinStronghold.slnx --no-restore -c Release
```

Run tests:

```powershell
dotnet test .\GoblinStronghold.slnx --no-build --no-restore -c Release
```

Run the headless scenario:

```powershell
dotnet run --project .\src\GoblinStronghold.Headless\GoblinStronghold.Headless.csproj --no-build --no-restore -c Release
```

Benchmark one complete demo day without rendering:

```powershell
dotnet run --project .\src\GoblinStronghold.Headless\GoblinStronghold.Headless.csproj --no-build --no-restore -c Release -- --benchmark-day
```

Build and open the Godot sandbox with the detected local editor:

```powershell
.\run-goblin-stronghold.ps1
```

The sandbox starts with one food stockpile at the goblin spawn and deterministic loose brushwood scattered across fertile land, including a small reachable starter supply. Left-click a visible goblin to select it and open its resizable, scrollable detail window. Left-click a stockpile on any discovered cell, including one currently under fog, to configure its target quantity, optionally reserve incoming deliveries for one named goblin and optionally select one compatible upstream stockpile. Without an explicit source, requested goods may come from loose stacks or surplus above any other stockpile's target. **Praca…** provides draggable gather-food, gather-brushwood, uproot-bush, tree-and-stump felling and clear-designation tools; food targets include berries, mushrooms, edible roots and fish shoals. Previously explored but currently unseen cells use the same interaction policy as visible cells for inspection, construction and work marking, while wholly unknown terrain is excluded. Harvested berry bushes remain visible without fruit and regrow berries in summer; mushrooms regrow in spring and autumn, roots outside winter and fish throughout the year. Uprooting permanently removes the bush and earns building experience. The felling selector retains only concrete trees and dead swamp stumps. One starting goblin has the tribe's wooden axe and provisional building competence, finds a reachable cardinal work cell beside each reserved target, and turns a living tree into a physical stump plus one sixteen-piece wood stack per trunk level. Harvesting a pre-existing or previously created stump removes it and yields a deterministic 8–16 pieces of wood. Satiated goblins do not gather wild food without a designation, while hunger may still create emergency foraging. Right-click no longer opens construction or issues a default movement order: a click cancels the active tool or clears selection, dragging pans the camera, and right-clicking inside a detail window closes that window. Future movement returns through explicit or contextual move, patrol, attack and occupy actions. Food and wood stockpiles each cost 2 wood. Wooden walls are laid as a dragged cardinal line, cost 2 wood per independently simulated segment and become solid navigation obstacles. A one-wood doorframe connects to neighboring walls, remains passable and can atomically replace an already completed wall segment. A separate one-wood door leaf can then be built in that frame; it starts closed and left-clicking it orders an open/close toggle. A wooden walkway costs 1 wood per cell, uses connected illustrated tiles and is laid by dragging from its first to its last cell; it may cross both land and water. Escape also cancels the active tool.

The game now opens on a full title menu rather than immediately entering the generated sandbox. It offers a new world, latest manual save load and exit; after a session starts it also offers return to game. `Esc` opens the same paused menu when no tool gesture is active, while the compact in-game session panel retains **Menu** and **Zapisz**. **Nowa gra** first protects an existing session with an autosave and then creates a new random seed. **Zapisz** (`F5`) writes `quicksave.json`; **Wczytaj** (`F9`) prefers that explicit manual save and uses the three rotating autosave slots, newest first, only as recovery fallbacks when the quicksave is missing, damaged or incompatible. Autosaves occur no more often than every ten real minutes and use atomic temporary-file replacement. Godot stores these files under its per-user `user://saves` directory rather than inside the repository. Every save carries an explicit format version and the world seed needed to reproduce its immutable baseline. Before the first shared build, the accumulated pre-release migration chain was deliberately removed and format 63 became the exact compatibility baseline. The simulation rejects every other save and map-generator version; the title menu ignores those candidates rather than offering a broken Continue action. Future post-sharing format changes must add deliberate forward migrations from this baseline. Replacing a session clears non-authoritative interpolated actor and animal positions before applying the loaded snapshot, so a marker cannot animate from a later abandoned position after load.

Current save recovery supersedes the earlier quicksave-first rule. The loader selects the highest saved simulation tick within the most recently written world, then falls back across other worlds and damaged slots. The title menu names that default candidate and exposes its tick in the button; a separate recovery picker lists every manual save, backup and rotating autosave with timestamp, world seed and deepest excavated Z, and loads only the explicitly selected slot. A second manual save atomically preserves the previous `quicksave.json` as `quicksave-backup.json`; every write is read back and byte-verified before success is reported. Replacing an active session first preserves it in the rotating `session-before-load.json` / `session-before-load-backup.json` pair after the target save validates, so loading an older point cannot erase the game that was just running or overwrite the selected recovery source. The rotating autosaves and all recovery backups participate in selection, but candidates outside the exact format-62 baseline are ignored.

`F3` or the **3D** button beside the session controls switches to an experimental renderer driven by the same authoritative map and simulation snapshot. It batches terrain into 16×16-cell meshes, gives ramps and cliff faces physical geometry, renders water as a separate translucent surface and batches the currently simple cutaway structure geometry without roofs. Goblins use lightweight 3D markers and remain selectable; camera pan, zoom and minimap navigation work in either renderer. The 3D probe starts with a strictly top-down orthographic camera. `F4` or the angle button compares it with the oblique view, while `Q`/`E` or the adjacent arrows rotate either camera mode in exact 90-degree steps. The stable 2D renderer remains the startup default and the button always permits an immediate return. This first probe intentionally renders the complete surface without fog, cave cutaways, textured materials, animated water or sprite-based furniture. Those are renderer concerns rather than a second simulation model; later digging can invalidate only affected terrain chunks, while furniture and foliage may use billboarded sprites or instancing above structural 3D walls. Isometric projection and rotation are deliberately not applied to the established 2D renderer until the experiment proves that their readability benefit justifies rotated assets, selection transforms and construction-preview changes.

World atlases now have a deterministic build-time baking pipeline. Run `tools/bake-assets.ps1` to execute its recipes sequentially through headless Godot. The connected-tile recipe `AssetRecipes/connected-walkways-v1.json` takes the six authored walkway shapes, expands them into all sixteen directional connection masks and produces bogwood, oak and pine material rows. The generated PNG is used directly by the 2D renderer, so it no longer rotates the reduced shape set while drawing. The geometry-aware `terrain-height-transitions-v1.json` recipe samples meadow, deciduous-floor, conifer-floor and bog textures, then produces all sixteen 4-bit high-edge combinations per material through deterministic displacement, directional shading and edge treatment. Current one-direction ramps use masks 1, 2, 4 and 8 immediately; corner, opposing-edge and multi-edge cells are already available for later terrain editing. Cliff faces remain a between-cell overlay rather than being incorrectly baked into one tile. The `cave-walls-v1.json` recipe interprets the same north/east/south/west bits as open cave neighbors. It rotates the authored frontal rock face toward each exposed edge and blends multiple orientations for corners, opposing faces, tees and isolated rock columns, producing sixteen masks for both sandstone and granite. The underground renderer selects these generated regions directly from cave topology. `connected-structure-walls-v1.json` applies the shared connection convention to human oak and goblin bogwood construction rows. Human buildings whose logical door faces south retain their stronger whole-room illustration; other orientations now render from authoritative floor, wall, door and roof parts, with separately drawn passable doorframes instead of rotating furniture and painted lighting. The existing walkway-derived master is an integration-quality placeholder: an artist can replace it with thinner plaster/timber and wattle source shapes without changing recipes, masks or renderer code. JSON manifests record every material/topology rectangle and a SHA-256 hash over the baker version, recipe and source atlas. Generated atlases are build/package inputs rather than per-user first-launch work: production packaging should bake and validate them before distribution. Player-built door leaves are separate interactive world objects rather than part of the frame texture; their current procedural rendering is ready to be replaced by authored open/closed sprites. Seasonal color, wetness, damage and dirt should remain shader or overlay parameters where possible instead of multiplying every baked combination.

Player-built wall rendering classifies connections, enclosed-room sides, sides covered by solid structures and final visible faces independently from atlas-mask selection. A cardinal flood fill starts at every unblocked map-edge cell; non-wall and non-solid cells it cannot reach form enclosed interiors. Room-facing sides take precedence. Without a room, a free-standing straight wall exposes both sides, an elbow exposes the inside of its angle, a tee exposes the missing-arm side and a cross retains only its neutral top. Solid material suppresses its adjacent face, leaving the empty side visible; this is the extension point for masonry built against cave rock. Doorframes participate in the enclosure boundary regardless of door state, so opening a door does not visually invert the room. The analysis is cached by the actual barrier and structural-solid position sets rather than the general world version. Cave rendering supplements the sixteen cardinal wall masks with diagonal inner-corner detection: when a rock cell touches open cave space only diagonally, the renderer draws the matching atlas corner quadrant instead of leaving a square dark notch.

New worlds also scatter deterministic small stone stacks across traversable land and place solid natural boulders. Small stones use an explicit area designation and the ordinary hauling pipeline. A designated boulder requires the provisional primitive pickaxe and yields 16–32 physical stone units when removed. The dedicated 64-unit stone stockpile costs 2 wood. One goblin receives a starter pickaxe for the playable prototype; capture of the corresponding tool from the human village remains the intended replacement once equipment loot exists.

The stockpile settings distinguish a local destination priority from the tribe-wide priority of the accepted resource. Editing the latter through one stockpile changes that resource policy for every hauling decision. A newly completed specialist food, wood or mineral stockpile enables pulling by default and requests goods up to its full capacity; the player may immediately lower the target or disable pulling. Field camps retain their expedition-sized target rather than blindly filling every provision slot.

Goblin huts and field camps are stationary fog observers with a configurable radius of three cells. This is part of the vision settings rather than a universal building rule: stockpile zones, walkways and natural objects do not reveal terrain. Later watch posts, occupancy, light sources and per-structure day/night ranges can use the same observer pipeline.

Field camps may now be built on any discovered, traversable 2×2 footprint, including cave floors. An underground camp keeps its physical floor, provision stockpile, five-goblin expedition capacity, rest function and fog observer, but does not add a redundant roof below the cave ceiling. Separate pickaxe work orders carve a persistent ramp down from a traversable floor or up from a deeper cave floor. Completion excavates the rock cell on the other side, yields physical stone, increments topology state and creates a bidirectional Z edge used by ordinary movement, hauling and construction. These player-made passages are authoritative save data and render on both connected levels.

Map generator version 9 introduces the coordinate foundation for material hills. A generated terrain column currently exposes its initial top through the transitional `SurfaceLevel` value, while every coordinate from base level up to but excluding that top is a deterministic sandstone or granite rock cell. These strata participate in the map fingerprint. Fog storage reserves stable positive-Z layers after the legacy surface and cave layers, and loading an older visibility array expands the missing hill layers as unknown without disturbing its earlier visibility history.

`SurfaceLevel` is generator input, not a privileged runtime layer. The generator's column representation must be baked into the same volumetric world used for caves, construction and excavation. At runtime a coordinate describes solid material, open volume, fluid and any explicit horizontal support or thin cover; a roof viewed from below is the same physical boundary as a floor viewed from above. Apparent terrain is derived from geometry and exposure to the sky. Sunlight, rain, gravity, water and lava therefore have no level-zero exception. A shallow body occupies volume over a traversable bed, while deep water requires open volume down to a lower bed rather than a special deep-water tile.

Hillside mining is now playable through the same volumetric contract as cave excavation. A raised `SolidGround` or `Mud` column has an occupiable cover at its material surface and a deterministic sandstone or granite mass at every lower non-negative Z coordinate. Mud is currently a thin surface cover over that rock core rather than a separately excavated soil volume. Exposed cells accept the ordinary pickaxe designation; excavation creates persistent traversable cave floor, yields physical stone, invalidates navigation and renders the same generated wall topology as underground rock. A single area order may continue through selected hidden cells as successive fronts become accessible. The legacy `SolidGround`-only hill fingerprint remains stable so existing generator-v12 saves load into the corrected geometry instead of being rejected. Dedicated soil, clay and peat volumes, shovel work, unstable earth walls and reinforcement remain a later material-system slice.

Generator version 10 begins that bake through one level-independent initial-cell geometry query. Terrain relief takes precedence over cave backing where old arrays overlap: a negative-level depression remains its actual exposed floor, and a deep-water column materializes fluid-filled open cells down toward its bed instead of becoming an unrelated cave cell. Solid hill strata, unsupported air and cave floors use the same result shape. Initial sky exposure is derived by tracing upward through open volumes and real vertical openings; it is not inferred from `z=0`. Natural cave mouths are now selected on an actual flat level-zero floor because the current cave connector descends exactly one level. Their placement prefers distance from both settlements, preserving enough buildable space even on the supported 16×16 minimum map. Current caves also guarantee at least one exposed coal face and one exposed iron-ore face instead of allowing every generated deposit to remain sealed behind arbitrary rock. Generator version 9 retains its former entrance placement and deposit distribution for save reproducibility; future hillside mouths require explicit lateral openings or a complete stepped shaft rather than a coordinate alias.

Generator version 11 makes that material relief playable in the established 2D slice view. A column's authored ground texture is drawn only on its actual `SurfaceLevel`; lower slices expose an unexcavated soil or rock cross-section and remain unknown under fog until opened. Positive terrain levels participate in `Page Up` / `Page Down` bounds even when no structure reaches them. Actor pathfinding maps each horizontal step to the neighboring column's actual surface and crosses a one-level difference only through the generated ramp direction, so goblins can climb a gentle slope, reveal its upper layer and later descend it as ordinary movement. The same rule deliberately recognizes a depression surface at negative Z before treating that coordinate as cave backing; save validation for excavated ramps follows the physical surface rather than assuming that every negative coordinate is underground. Generated plants and natural structures still retain legacy column anchors internally and are projected onto the column surface by rendering and occupancy compatibility; migrating their authoritative anchors and all ecology movement to material Z is a later cleanup.

Baseline navigation for generator version 10 now addresses the actual supported coordinate of each terrain column. A ramp edge therefore connects positions whose Z values differ by one, a cliff exposes no such edge, and a negative-level exposed floor can also join a genuinely open cave volume beside it at the same Z. Historical generators retain their legacy `z=0` surface address so existing actor saves do not change meaning. Only the guaranteed demonstration spine on the first cave level detours around columns occupied by two-level surface water; this preserves one testable route into the underground on every valid map, not a rule that caves must be dry. Chambers and future branches may remain partially or completely flooded. The common direct corridor remains cheap, while only an obstructed guaranteed route invokes the deterministic local detour search. Purpose-authored underground rivers will later use explicit fluid cells and hazards instead of accidental array overlap.

The current path services remain omniscient compatibility services while actors still use the legacy spatial model. The actor migration must not expose those services as agent knowledge. Its replacement boundary has an authoritative local path query plus personal and group belief graphs. Believed edges record endpoints, last observation tick, reporter and confidence; they become stale without being silently rewritten when world topology changes. An actor verifies only a bounded neighborhood, records a failed transition and replans locally. Sharing that failure requires a later deterministic report event at a camp, settlement, meeting or communication facility. The UI and dispatcher will distinguish known, believed, uncertain and locally blocked feasibility. Exact report schemas, perception radius and communication latency belong to the actor-migration slice rather than generator version 10.

The first actor-knowledge foundation now stores canonical local edges independently of travel direction, with passable, blocked or hazardous status, observation and receipt ticks, source actor, confidence and direct-versus-reported provenance. Conflicting entries resolve deterministically and freshness derives from observation age rather than delayed delivery. Every successfully traversed edge becomes a direct personal observation; a transition rejected at execution becomes a personal blocked observation and triggers a local replan that excludes personally known blocked edges without polluting the shared authoritative route cache. Explicit and resumed movement plus point-to-point autonomous routes for needs, raids, hauling, construction, crafting, hunting and bud care use the actor's personal belief first and tribal knowledge as a fallback. Positive observations do not change connectivity and therefore retain the shared topology-versioned route cache; an actor-specific filtered search is paid only while personal or tribal knowledge contains an actual blocked edge. Multi-target searches such as nearest edible plant or exploration frontier still use their omniscient compatibility BFS until those services accept the same belief filter.

Observed edges enter a per-actor pending-report set rather than tribal knowledge immediately. A goblin delivers those reports only while physically standing on a traversable floor or doorway belonging to a tribal hut or field camp. The shared record retains the original observation tick and source but receives its own later delivery tick and indirect provenance. Personal beliefs, undelivered report sets and tribal beliefs are authoritative save-format-35 state and participate in the deterministic simulation hash. Strategic selection of a raid rally camp already uses the tribal belief graph, while each marching goblin may override it with a personal observation. Meetings between traveling groups, dispatcher processing latency, explicit messenger jobs, a true coarse region graph and public feasibility presentation remain later slices.

The unified fluid contract permits underground rivers, reservoirs and lava channels; none are implemented as dynamic sources by generator version 10. A hidden body will remain absent from fog and selection until normally discovered, while solid material may accumulate derived moisture or temperature and expose only local symptoms such as dripping, a seepage puddle, a hot wall or glowing cracks. Permeability and heat conduction are slower solid-boundary processes. Excavating the final separating cell instead creates a full flow connection governed by fluid amount, head and gravity. These fields belong to dirty fluid and thermal regions, not to a global per-tick scan. Crossing above the hazard, digging an independent route, draining by gravity into a lower outlet or sump, building a bulkhead and eventually pumping into another bounded volume are physical mitigations rather than scripted exceptions. No drying job may destroy water without a configured outlet or storage capacity.

Generated deep-river volume now also wins over the legacy cave array at runtime. A depth-two river intersecting `z=-1` is rendered as animated underground water, is neither traversable nor mineable rock, and retains that interpretation when an older save already lists the coordinate among excavated cave cells. This fixes the physical riverbed intersection without yet simulating propagation into newly connected neighboring cells; flooding, pressure, draining and seepage remain responsibilities of the future dirty-region fluid subsystem above.

The current `demo-temperate` climate profile gives every season 10 days. At `1×`, each of its days lasts 19 real minutes: 12 minutes of daylight followed by 7 minutes of night, with dawn at 05:00. These are demo data, not calendar invariants. Every climate season independently defines its day count, daylight and night tick lengths, dawn and dusk civil times. The calendar resolves variable day boundaries without a global modulo, while the centered annual HUD sizes its seasonal bands from the profile's actual time proportions. This is the extension point for future map climate zones and season-dependent photoperiods.

Goblin sight is reduced at night; human cohorts use short-range lantern light. Two carried food portions and two waterskin portions cover roughly one demo-temperate day. Untreated dehydration becomes fatal after about three such days and starvation after about ten. A typical goblin reaches forced sleep after roughly one and a half days awake; huts and field camps provide proper rest, while an exhausted goblin that cannot reach shelter collapses where it stands. Illness and accident consequences of exposed sleep remain a later simulation slice. Need rates remain simulation-definition data and will require climate-aware calibration when non-demo profiles become playable.

A field camp prepares at most five goblins for a raid. The raid action opens an explicit party picker; the chosen actor ids are simulation state and survive save/load. Its live summary explains whether each member is still traveling, unloading, eating, drinking, resupplying or resting. The selected party provisions, rests and rallies there before marching on the village; other tribe members remain available to the ordinary work dispatcher. A raider whose urgent needs interrupt movement resumes the expedition instead of falling back into public work, and the camp can recall an already marching party into an editable suspended plan. Engagement uses concrete human bodies rather than only the aggregate guard total. Ordinary encounters and the guard-only doctrine retain defender-only targeting; the non-fleeing doctrine additionally admits a civilian who is not currently fleeing and lies inside the configured raid radius. Human retaliation and goblin attacks are independent phases, so the lack of an on-duty guard does not cancel a valid raid strike. Eliminating the aggregate guard cohort enters a dedicated looting phase when a defeated human body or targeted village building retains contents selected by the raid doctrine. A surviving raider walks to the exact corpse or a traversable interaction cell beside the structure, spends physical handling time, removes a bounded concrete stack, carries it back to the rally camp and drops it there. Human bodies expose eight authoritative raw-meat portions. The corpse-consumption directive reserves one exact body at a time, sends a raider to it and consumes one portion per completed eating cycle; satiety changes through the ordinary raw-meat nutrition rule, partially eaten bodies remain physical, and their remaining portions survive save/load. Corpse handling is now an explicit exclusive mode: recover the body unchanged to camp, recover and pollinate it at camp, pollinate it where it fell, or leave it. Looting and configured eating happen before that final handling. The goblin completing pollination is stored as the bud's parent while the removed corpse contributes an independent immutable imprint of its carrier's skills, traits, experience and work predispositions. Maturation resolves partial inheritance from both sources. Save-format 56 persists these imprints on bodies and buds; migration from format 55 deliberately leaves historical imprints empty rather than fabricating lost knowledge. After all selected loot and bodies are secured, the raid enters a separate returning phase; victory closes only when every survivor has physically reached the camp. Carry state, active aftermath work and the return phase survive save/load and participate in deterministic hashing. Food, timber and basic materials are removed from the authoritative village economy, while stolen tools are separately persisted and therefore do not reappear after load. Losing every selected raider still closes the raid as a defeat. Save-format 55 introduced persistent goblin and human corpses. A body is a searchable physical container retaining equipped tools, provisions, water, ammunition and carried cargo; those contents no longer teleport into loose ground stacks on death. The Godot map, inspector, status and raid window expose bodies, remaining meat, building contents, looting, corpse-origin buds and return. General non-raid area orders for recovering or pollinating arbitrary discovered bodies, explicit player storage destinations, pursuit and voluntary retreat, civilian surrender, fire and occupation remain later slices.

## Deterministic contract

- Simulation time advances through fixed integer ticks.
- Commands target future tick boundaries and are ordered by an explicit sequence.
- Random samples are keyed by world seed, subsystem domain, stable entity, tick and sample key.
- Simulation detail and update frequency never consume a mutable RNG stream; future coarse systems use stable logical intervals or scheduled-event identities.
- Render speed and snapshot frequency do not participate in authoritative state.
- State hashes exclude the event delivery buffer, so observing or draining events cannot alter the world.
- Saves include pending commands and undelivered events.
- Normal, accelerated and unthrottled runners must agree for the same command schedule.

Timing metrics are diagnostic and deliberately excluded from saves and state hashes.

### Underground gameplay update

This update supersedes the earlier cave-preview limitations in this file. Actor movement, hauling, survival trips and construction now share a cached terrain route across the explicit `z=0`, `z=-1` and `z=-2` passages. A cave mouth, stair or natural ramp is an ordinary navigation edge rather than a special travel order: a job on a discovered level pulls its worker and materials through the required passage automatically. Underground wooden walls, stone walls, frames, doors and wall torches participate in the same topology, including automatic door opening during travel. Their connected sprites, door leaves and enclosure-facing analysis are evaluated only against the currently rendered level rather than being hard-wired to the surface. Fog state is stored independently per underground level. The explicit movement toolbar action lets a selected goblin receive a destination on another visible level, while `Page Up` and `Page Down` preserve that selection. Cave views now pass through the ordinary structure, actor, loose-item, stockpile, construction, work-order and fog layers after drawing cave terrain; only surface vegetation, human cohorts and the day/night overlay are omitted. Their toolbars expose underground stockpiles, wooden and stone barriers, doors, wall torches, gathering of loose wood and mineral output, rock excavation and clearing orders; surface-only camps and walkways remain unavailable there.

Food, wood and stone stockpile blueprints on explored cave floors generate ordinary physical delivery and construction work. Rock excavation is an area designation over concrete discovered solid cells. A selected rock cell remains queued even when it is not yet exposed; the dispatcher considers it feasible only after an adjacent cell becomes traversable, so one area order can advance into a tunnel without inventing targets beyond the originally selected cells. A pickaxe-equipped goblin works from that adjacent open cell, changes the target into persistent traversable floor, invalidates navigation topology and leaves a physical stone stack. Excavated cells, pending and active jobs, routes, cargo, visibility and unfinished underground construction are part of deterministic hashes and saves.

The resource statistics windows now switch between grouped totals and concrete variants. Grouped mode combines all food, wood or mineral material while its tooltip retains the breakdown; detailed mode separates food kinds, oak, chestnut, birch, walnut, apple and pine wood, sandstone, granite, coal and iron ore. Wood species remain material identity rather than a texture-only choice so trunks, boards, buildings and furniture can later inherit their color and properties. Stack splitting, hauling, storage and save/load preserve this identity.

Generator version 8 adds clustered coal and iron-ore veins as a separate property of solid cave rock. Exposed veins receive a lightweight wall overlay and the inspector identifies them. Mining still yields ordinary sandstone or granite, plus a separate coal or iron-ore stack; the mineral stockpile can independently accept or reject sandstone, granite, coal and iron ore. The policy affects new deliveries without destroying contents already stored, is deterministic and survives save/load. Generator version 7 remains reproducible without deposits for existing saves. Smelting, fuel consumption, ore grades, additional metals and reusable stockpile-policy presets remain future production-system work.

Primitive-workshop products now appear as physical equipment stacks on the workshop floor instead of entering the crafter's inventory magically. This supersedes the earlier direct-assignment note above. Haulers can move products into a dedicated equipment stockpile with eight item-type slots holding four pieces each; a newly built stockpile pulls up to its full 32-piece capacity, and idle adult goblins collect useful equipment they do not yet carry. Equipment variants, stockpile contents and in-progress provisioning survive save/load; format 53 adds the new resource priority to older saves.

Walkway blueprints are level-relative rather than surface-only. They may cover water, ordinary ground or unsupported open cells such as ravines and excavated gaps on any materialized level, but never solid rock or an occupied surface/solid channel. Each segment remains an independent one-wood construction job, so builders extend a crossing from reachable ground or previously completed segments. A completed elevated or subterranean walkway becomes an ordinary bidirectional navigation surface at its exact `Z`; this supersedes the earlier surface-only limitation above.

Basalt walkways add the first fireproof construction material. Their linear placement and segment ordering use the same level-independent bridge contract as wooden walkways, but lava is a valid foundation. Each segment requests one physical `Basalt` stone variant rather than accepting generic stone, takes longer to build and requires Building level 2 plus either a primitive or reinforced pickaxe. Completed basalt segments use the ordinary walkway occupancy and navigation edge, render with a distinct gray stone tint, and persist as their own append-only construction and world-object enum values. World-object restore validation now follows the map's materialized lower bound instead of rejecting every part below `z=-16`.

The title and recovery flows also show load exceptions in a modal dialog instead of relying on the in-game inspector hidden behind the main menu. Both user quicksave slots that exposed this bug were loaded and advanced through the headless profile after the fix.

Material-derived construction rendering now completes the first visual-consumer slice without changing save format 65. Connected wall atlas regions are cached per topology and concrete material, while illustrated huts and field camps selectively replace timber-colored pixels and preserve unrelated authored details. Frames, door leaves, wall-torch handles and interior wall faces use the same authoritative edge/shadow/midtone/highlight palette. Natural boulders use the neutral gray stone cluster in the item atlas as a keyed authored master rather than rebuilding the shape from procedural circles; cached sandstone, granite, basalt and obsidian appearances retain the source cracks and facets. Barrier render caches retain world objects rather than only positions, allowing adjacent segments made from different woods or rocks to remain visually distinct. Goblin structure illustration levels are relative to the object's anchor rather than hard-coded to surface levels.

The construction-material-identity slice supersedes the earlier format-64 compatibility statement: format 65 is now the exact pre-release save baseline. It adds the first-delivered material lock to durable construction sites and persists the concrete material variant on completed world objects without restoring the discarded migration chain. Storage-zone and placed-water requesters remain intentionally material-agnostic because their output is not a material-bearing structure.

Logistics-network authority advances the exact save baseline to format 66. Every unclaimed storage destination belongs to the canonical `Default` network, whose workforce is all adults not explicitly assigned to a specialist network. Each specialist belongs to at most one non-default network; those networks own explicit source-store sets and target stores, while old per-store hauler and source overrides remain stronger local constraints. Hauling candidate selection, specialist-duty priority, diagnostics, snapshots, hashes and save/load all use that policy. This is deliberately the routing layer only: the next spatial layer replaces isolated capacity spots with multi-cell storage areas whose boxes, chests, bins and barrels provide physical solid or sealed-liquid slots, followed by the Godot management window for naming networks and editing rosters, sources, targets and filters.

Storage-area authority advances the exact save baseline to format 67. An area owns a bounded rectangular same-level footprint and one logistics network, while its member storage providers retain the existing resource filter, slot policy, priority and local hauling overrides. Existing one-cell stockpiles automatically become singleton starter areas without consuming a second entity identifier. A newly designated empty area contributes no abstract capacity; placing a storage provider on one of its cells attaches it to the area and inherits the area's network. Changing either a member's network through the compatibility command or the area directly updates every provider in that area. Footprints, membership, aggregate capacity and stored quantity are exposed in snapshots and preserved in deterministic hashes and exact save/load. This foundation deliberately does not yet claim physical boxes, chests or bins, Godot footprint designation/rendering, area naming, or the full logistics control window.

Physical solid-container identity advances the exact save baseline to format 68. The primitive workshop can make a two-wood/one-reed box, a four-wood/one-reed chest and a three-wood/two-reed bulk bin. The completed equipment remains a loose haulable stack until a matching placement blueprint requests it; only delivery and installation create a provider inside the containing storage area. Boxes expose four typed stacks of eight, chests eight typed stacks of eight and bulk bins one homogeneous stack of 64. Provider kind, slot policy and area membership survive snapshots, hashing and exact save/load validation. The Godot build menu can designate rectangular areas up to 256 discovered traversable cells and place all three containers, while the 2D view separates the translucent area footprint from schematic box, chest, bin and barrel marks. Filters remain the existing provider-level acceptance policy; editing them, naming areas and networks, and the consolidated logistics control window remain the next management slice.

Logistics management advances the exact save baseline to format 69. Simulation commands now carry an optional bounded text payload that is accepted only by authoritative rename operations and is included in pending-command persistence and deterministic hashing. Specialist networks and storage areas can be uniquely renamed; physical boxes, chests and bulk bins can change their future-delivery resource filter without destroying incompatible contents already inside. The canonical `Default` network cannot be renamed or receive an explicit specialist roster/source list. A consolidated Godot window creates specialist networks, edits their names, toggles adult haulers and approved source providers, assigns whole areas to networks, renames areas and edits container filters. This remains deliberately non-destructive management: network/area deletion, footprint resizing and compound category/variant expressions are deferred.

The logistics lifecycle slice retains save format 69 because it adds no persisted fields. Deleting a specialist network releases its exclusive haulers and atomically returns every destination area/provider to `Default`; source membership disappears with the network, while physical stacks and provider settings remain untouched. A storage-area resize is authoritative only when its new same-level footprint is traversable, does not overlap another area and still contains every installed provider. Dissolving an area removes only its shared footprint identity: providers at each occupied cell become a safe singleton area in the same network, retaining filters, priorities, local assignments and contents. Empty areas disappear outright. The Godot logistics window exposes all three operations, and resizing reuses the persistent drag tool with right-click/Escape cancellation. Compound category/variant filter expressions remain deferred.

Compound container categories advance the exact save baseline to format 70. Every storage provider now persists and hashes an authoritative resource-category mask while retaining its single-resource display preset for compatibility with specialized food, stone, materials and water behavior. Boxes, chests and bulk bins expose independent category checkboxes in the logistics window; their expression is an OR across selected solid-goods categories, must retain at least one category and affects only future deliveries. Existing incompatible contents remain physical and untouched. Dispatcher source selection, delivery diagnostics, explicit-source compatibility, work readiness and save validation all use the same mask. Exact food/material variants remain the next filter layer rather than being encoded into category names.

Tracked surface grime advances the save baseline to format 71. Format-70 saves have a deliberate forward migration that initializes empty grime state for every mover; both the simulation loader and title/recovery candidate scanner accept them, while the next successful save writes format 71. Walking from dry ground, mud or an open mine loads one neutral gray-brown dirt amount onto a mover; constructed floors and walkways receive diminishing deposits, while sufficiently dirty surfaces can carry the contamination onward. Goblins, human villagers and every simulated animal species—including underground fauna—use the same transfer policy through their respective movement loops. Water clears carried blood and grime. Surface grime, timestamps and each mover's carried amount participate in snapshots, deterministic hashing and exact save/load. The existing save-compatible `CleanBlood` designation now means general surface cleaning and removes both blood and tracked dirt. The 2D view renders grime from a neutral recoloring of the existing splatter-mask atlas below the blood layer, without multiplying variants by source material.

Resource overviews now default to concrete type breakdowns and use a three-column scrollable tile grid. A dedicated transparent food atlas distinguishes dried rations, berries, mushrooms, roots, fish and raw meat. Wood species reuse the authored bound-log silhouette with palette replacement limited to its timber pixels; stone, ore, gem and metal variants reuse the neutral stone silhouette with complete palette replacement from `materials.json`. Storage-detail contents use the same resolver and aggregate identical `(resource, food, variant)` stacks into icon-and-count slots, three per row. The storage window title names the concrete provider and uses a provider glyph instead of the generic settings caption. Planks and material families that need a silhouette other than the current keyed stone master remain future authored atlas work.
